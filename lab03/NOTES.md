# NOTES: сравнение версий (пункт 2)

## git log --oneline --stat
Показывает краткую историю коммитов и статистику по файлам (сколько строк добавлено/удалено).  
Наблюдение: в коммите `feat: add multiplication to calc.py` изменено 2 строки в `lab03/calc.py`; в коммите с вычитанием — тоже 2 строки; в базовом — 3 строки.

## git diff HEAD~2 HEAD -- lab03/calc.py
Сравнивает состояние файла 2 коммита назад и текущее.  
Наблюдение: добавлены блоки `elif` для вычитания и умножения; логика расширена без удаления старых строк.

## git show HEAD~1
Показывает полный diff и метаданные предпоследнего коммита.  
Наблюдение: в этом коммите (с вычитанием) добавлен блок `elif op == "-": print("Результат:", a - b)` и ввод операции.

## git log -S"def" --oneline -- lab03/calc.py
Ищет коммиты по строке "def".  
Наблюдение: вывод пустой, потому что в коде нет функций с `def`.

## git blame lab03/calc.py
Показывает, в каком коммите и кем была добавлена каждая строка.  
Наблюдение: строки 1–3 добавлены в первом коммите; строки 6–7 (вычитание) — во втором; строка 8 (умножение) — в третьем.

# NOTES: работа с историей и откатом (пункт 3)

## git show HEAD~3:lab03/calc.py
Показывает содержимое файла из самого первого коммита.  
Наблюдение: в этой версии есть только сложение; операции вычитания и умножения ещё не реализованы.

## git checkout HEAD~1 -- lab03/calc.py
Временно переключает файл на версию из предпоследнего коммита.  
Наблюдение: после этой команды в коде остаётся только вычитание; умножение исчезает. Это позволяет быстро посмотреть предыдущее состояние без потери истории.

## Возврат к актуальной версии
Команда `git restore --source=main lab03/calc.py` (или `git checkout`) возвращает файл к текущему состоянию ветки main.  
Наблюдение: умножение снова появляется; файл соответствует последнему коммиту.

## git log --oneline --follow -- lab03/calc.py
История изменений именно для файла calc.py.  
Наблюдение: видны все коммиты, которые меняли calc.py (добавление сложения, вычитания, умножения). Удобно для отслеживания эволюции конкретного файла.

# NOTES: работа с ветками (пункт 4)

## git branch feat/division && git checkout feat/division
Создаёт и переключается на новую ветку `feat/division`. Это позволяет разрабатывать новый функционал отдельно от основной ветки `main`.  
Наблюдение: ветка создана; все последующие коммиты идут в `feat/division`.

## Добавление деления
В ветке `feat/division` добавлена обработка операции `/` с проверкой на деление на ноль.  
Наблюдение: код стал безопаснее; в `main` этого изменения пока нет.

## git diff main..feat/division -- lab03/calc.py
Показывает различия между ветками только для `calc.py`.  
Наблюдение: видны добавленные строки с обработкой деления; других изменений нет. Удобно для ревью изменений перед слиянием.

## git merge feat/division (в main)
Объединяет изменения из `feat/division` в `main`.  
Наблюдение: выполнено fast-forward слияние; функционал деления теперь в `main`; конфликтов не возникло.
